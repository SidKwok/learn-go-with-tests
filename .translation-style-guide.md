# Translation Style Guide (English → 简体中文)

This file is consumed by translation subagents. It will be deleted after the translation work is done.

## Hard rules (must follow)

### 1. Code blocks (` ``` ` ... ` ``` `): KEEP CODE IDENTICAL
Do NOT translate any of:
- variable names, function names, type names, struct fields, package names
- Go keywords (`func`, `var`, `if`, `return`, `range`, etc.)
- standard library identifiers (`fmt.Println`, `testing.T`, `t.Errorf`, `*testing.T`, `t.Helper()`, etc.)
- import paths

What you MAY translate inside code blocks:
- comments inside Go code (`// ...`) → translate to Chinese
- `t.Run("description", ...)` — translate the description string to Chinese
- log messages or panic messages that are clearly user-facing prose

What you MUST keep verbatim inside code blocks:
- string literals that are the **subject of the lesson** (e.g., `"Hello, world"`, `"Hola, Elodie"`, `"Bonjour, "` — these ARE the teaching content; translating them breaks the chapter)
- assertion messages like `"got %q want %q"` — keep as-is so students see the exact compiler/test output
- error messages constructed by Go code (errors.New("..."), fmt.Errorf("..."))  unless they're clearly UI prose

### 2. Shell / terminal output blocks (```text, ```shell, no language tag): KEEP VERBATIM
Examples:
```
$ go test
go: cannot find main module; see 'go help modules'
```
These are real outputs students will compare against. Translate NOTHING inside these blocks.

### 3. URLs: NEVER MODIFY
- Keep all `http://`, `https://` links exactly as-is
- Keep relative `.md` links exactly as-is (e.g., `[text](hello-world.md)`)
- Keep image paths exactly as-is

### 4. Markdown structure: PRESERVE
- All heading levels (`#`, `##`, `###`)
- Lists (`*`, `-`, `1.`)
- Bold/italic markers (`**`, `_`, `*`)
- Link syntax `[text](url)` and `<url>`
- Image syntax `![alt](path)`
- Code fence language tags (` ```go `, ` ```text `, ` ```shell `, ` ```bash `)
- Tables (`|`)
- Blockquotes (`>`)

## Tone

- Technical but **approachable** — match the original author's casual tone
- Use 我们/你 freely (the author uses "we" and "you" a lot)
- Don't over-formalize; "let's" → "我们来" or "让我们来" or just rephrase naturally
- Exclamations OK ("！")
- Don't add hedging; if the author says something definitively, translate it definitively

## Common pitfalls

1. **Don't literal-translate idioms.** "by the way" → "顺便一提" not "在路边"; "out of the box" → "开箱即用".
2. **Don't translate inside backticks unless content is prose.** `` `func` `` → keep `func`. `` `Hello function` `` → "`Hello` 函数" — adapt structure naturally.
3. **Numbers and units stay English** ("Go 1.16", "200 OK").
4. **Author quirks to preserve**: footnotes, asides in italics (`_text_`), parenthetical jokes — translate but keep tone.
5. **Don't expand acronyms**: TDD stays TDD after first introduction; HTTP stays HTTP; API stays API.
